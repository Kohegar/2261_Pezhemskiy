### Задание 1 **(2)**
*Оцените работу следующих фрагментов программ. Какие из них обладают неоднозначным поведением? Почему?*
```
int x=10, y=3;
std::cout << std::min(x=15, x+y);
```
```
int x=10, y=3;
x=15, y+=x, x+=y;
```
```
int x=10, y=9;
if (x>y++ && y++>9)
  cout << "yes" << endl;
cout << y;
```

*Тексты программ разместите в папке с номером задания*

**Ответ:**

Первый фрагмент.

В `std::min` передаются два числа. При вычислении первого аргумента `x` становится равным 15. Во втором аргументе вычисляется `x + y`.

Если сначала вычислить `x + y`, получится `10 + 3 = 13`. После этого `x = 15`, а `min(15, 13) = 13`.

Если сначала выполнить `x = 15`, получится `x + y = 18`. Тогда `min(15, 18) = 15`.

Поэтому в C++17 и новее возможны результаты 13 и 15: компилятор сам выбирает порядок вычисления аргументов. В старых стандартах до C++17 этот код имел неопределённое поведение, потому что чтение и изменение `x` не были упорядочены.

При проверке с C++17 GCC 14.2 вывел 13, Clang 17 вывел 15.

Второй фрагмент.

Запятая здесь является оператором, который выполняет действия по порядку слева направо:

1. `x = 15`.
2. `y += x`: `y = 3 + 15 = 18`.
3. `x += y`: `x = 15 + 18 = 33`.

Получаем `x = 33`, `y = 18`. Неоднозначности нет.

Третий фрагмент.

`y++` сначала использует старое значение `y`, а затем увеличивает его на 1. `&&` проверяет условия слева направо. Если первая часть ложная, вторая не выполняется.

В начале `x = 10`, `y = 9`.

1. Проверяется `10 > 9` — истина. После `y++` значение `y = 10`.
2. Проверяется `10 > 9` — истина. После второго `y++` значение `y = 11`.

Обе проверки истинны, поэтому программа выводит:

```
yes
11
```

Неоднозначности здесь нет: порядок проверки частей `&&` определён.


### Задание 2 **(2)**
*Как записать следующие строки программы на С++ в виде одного
выражения? Приведите несколько способов, в том числе с использованием операторов инкремента.*
*Проверьте работу написанных программ*
```
x=x+1;
z=z+2*x+3*y;
y=y+1;
```
*Тексты программ разместите в папке с номером задания*

**Ответ:**

Нужно оставить тот же порядок действий: сначала увеличить `x`, потом изменить `z`, потом увеличить `y`.

Способ 1 — через запятые:

```
(x = x + 1, z = z + 2*x + 3*y, y = y + 1);
```

Способ 2 — через `++` и `+=`:

```
(++x, z += 2*x + 3*y, ++y);
```

Способ 3 — в одном присваивании:

```
z += 2*(++x) + 3*(y++);
```

`++x` сначала увеличивает `x`, а затем использует новое значение. `y++`, наоборот, сначала использует старое значение `y` и только потом увеличивает его.

Проверка: если сначала `x = 1`, `y = 2`, `z = 3`, после каждого варианта получаем `x = 2`, `y = 3`, `z = 13`.


### Задание 3 **(2)**
*Рассмотрите следующий фрагмент программы. Он заполняет вектор из 10 элементов единицами.*
```
std::vector<int> x(10);
for (int i = 0; i < 10;)
   x[i++] = 1;
```
*Перепишите ее так, чтобы в третьей строке использовался префиксный инкремент, но результат ее работы не изменился.*
```
std::vector<int> x(10);
for (...)
   x[++i]=1;
```

**Ответ:**

Исправленный вариант:

```
std::vector<int> x(10);
for (int i = -1; i < 9;)
   x[++i] = 1;
```

В исходном варианте `i++` сначала обращается к элементу с текущим индексом, а потом увеличивает `i`.

В новом варианте `++i` сначала увеличивает индекс, а потом обращается к элементу. Поэтому начинаем с `i = -1`: первое увеличение даст 0.

Далее получаем индексы 1, 2, ..., 9. В результате все 10 элементов вектора будут равны 1, как и раньше.


### Задание 4 **(2)**

*Почему присваивание* ```(++x)=y``` *является синтаксически правильным, а*
```(x++)=y``` - *нет? Запишите текст сообщения об ошибке, переведите и объясните его.*

**Ответ:**

Проверим два выражения:

```
int x = 1, y = 7;
(++x) = y;
```

Так писать можно. `++x` увеличивает `x` и возвращает саму переменную. Ей можно присвоить новое значение. В итоге `x = 7`.

А так нельзя:

```
int x = 1, y = 7;
(x++) = y;
```

`x++` возвращает старое значение `x` как временный результат. Присваивать значение этому результату нельзя.

Сообщение GCC:

```
error: lvalue required as left operand of assignment
```

Перевод: «Слева от присваивания требуется изменяемый объект (lvalue)».

Сообщение Clang:

```
error: expression is not assignable
```

Перевод: «Этому выражению нельзя присвоить значение».

Простыми словами: `++x` позволяет обратиться к самой переменной, а `x++` возвращает её прежнее значение, которому нельзя присваивать.


### Задание 5 **(2)**

*Программисты на Python для обмена значений двух переменных часто пишут строку*
```
a,b = b,a
```
*Проверьте, будет ли аналогичная строка на С++ (с точкой с запятой в конце) являться синтаксически
правильной? Будет ли она обменивать значения переменных? Как в языке С++ вычисляется это выражение?*

**Ответ:**

В C++ строка `a,b = b,a;` допустима, но она не меняет переменные местами.

Программа для проверки:

```
#include <iostream>
using namespace std;

int main() {
    int a = 1, b = 2;
    a,b = b,a;
    cout << a << " " << b;
}
```

Результат: `1 2`.

Почему? В C++ присваивание `=` имеет более высокий приоритет, чем запятая. Поэтому программа воспринимает строку так:

```
(a), (b = b), (a);
```

Сначала просто берётся `a`, затем `b` присваивается само себе, затем снова берётся `a`. Значения остаются прежними.

Для настоящего обмена в C++ можно использовать:

```
#include <utility>
std::swap(a, b);
```

Или третью переменную:

```
int t = a;
a = b;
b = t;
```


### Задание 6 **(2)**

*Проверьте работу следующего фрагмента программы*
```
  std::string s;
  for (int i=0; i<1000000; i++)
     s += 'a';
  std::cout << s.size();
```
*Измените третью строку на*
```
s=s+'a';
```
*Изменится ли что-нибудь в ее работе? Объясните результат.*

**Ответ:**

Оба варианта добавляют в строку миллион букв `a`, поэтому вывод будет одинаковым:

```
1000000
```

Разница в скорости работы.

` s += 'a'; ` добавляет букву к существующей строке. Этот способ обычно работает быстро.

` s = s + 'a'; ` обычно сначала создаёт новую строку из прежнего содержимого и новой буквы, а потом записывает результат в `s`. Поэтому при большом количестве повторений он обычно заметно медленнее и может использовать больше памяти.

Итог: содержимое и длина строки не меняются, но время выполнения может сильно увеличиться.


### Задание 7 **(2)**

*Как работает следующая программа? Как зависит результат от исходного значения?*
```
int x;
std::cin >> x;
x-->0 && x-->0 && x-->0 && x-->0 && x-->0;
std::cout << x;
```

**Ответ:**

Запись `x-->0` выглядит необычно, но в C++ это два оператора:

```
x-- > 0
```

`x--` берёт старое значение `x`, а затем уменьшает `x` на 1. После этого старое значение сравнивается с нулём.

Оператор `&&` проверяет части слева направо и прекращает проверку, как только встречается ложь.

Примеры:

- Начальное `x = 7`: выполняются все пять проверок, результат `2`.
- Начальное `x = 5`: выполняются все пять проверок, результат `0`.
- Начальное `x = 3`: проверяются значения 3, 2, 1, 0; на нуле проверка ложна, результат `-1`.
- Начальное `x = 0`: первая проверка ложна, но `x` уже уменьшился, результат `-1`.
- Начальное `x = -2`: первая проверка ложна, результат `-3`.

Общее правило:

- Если `x >= 5`, результат равен `x - 5`.
- Если `0 <= x < 5`, результат `-1`.
- Если `x < 0`, результат равен `x - 1`.

Последнее правило не применяется к самому маленькому возможному `int`: при его уменьшении происходит переполнение, и поведение не определено.


### Задание 8 **(3)**

*Какое число выводит следующий фрагмент программы? Посчитайте результат без использования
вычислительной техники. Отчет должен содержать процесс вычислений.*
```
int s = 0;
for (int i = 0, j = 5;i+j <= 16;(i<j ? i : j)++)
   (s += i) += j;
std::cout << s;
```

**Ответ:**

Ответ: `126`.

В третьей части цикла написано `(i<j ? i : j)++`. Если `i < j`, увеличивается `i`, иначе увеличивается `j`. То есть каждый раз увеличивается меньшая переменная, а при равенстве — `j`.

Выражение `(s += i) += j` сначала добавляет к `s` значение `i`, а затем добавляет `j`. Иными словами, за одну итерацию к `s` прибавляется `i + j`.

Посчитаем вручную:

| Шаг | i | j | Прибавляем | s |
|---|---:|---:|---:|---:|
| 1 | 0 | 5 | 5 | 5 |
| 2 | 1 | 5 | 6 | 11 |
| 3 | 2 | 5 | 7 | 18 |
| 4 | 3 | 5 | 8 | 26 |
| 5 | 4 | 5 | 9 | 35 |
| 6 | 5 | 5 | 10 | 45 |
| 7 | 5 | 6 | 11 | 56 |
| 8 | 6 | 6 | 12 | 68 |
| 9 | 6 | 7 | 13 | 81 |
| 10 | 7 | 7 | 14 | 95 |
| 11 | 7 | 8 | 15 | 110 |
| 12 | 8 | 8 | 16 | 126 |

После этого `j` увеличится до 9, сумма `i + j` станет равной 17, а условие `i + j <= 16` перестанет выполняться.

Проверка суммы без компьютера:

```
s = 5 + 6 + 7 + ... + 16
s = (5 + 16) * 12 / 2 = 126
```


###  Задание 9 **(3)**
*Рассмотрите следующую программу. Предполагается, что на вход подается некоторый
индекс в массиве - число от нуля до девяти и значение, которое надо записать по этому индексу.*
```
int i = 0;
std::vector<int> x(10);
std::cin >> i >> x[i];
std::cout << x[i];
```
*Проверьте работу этой программы на различных компиляторах. Найдите два компилятора (можно 
проверить онлайн компиляторы), на которых эта программа будет давать различные ответы при одинаковом
вводе. Как это объяснить?*

**Ответ:**

Здесь проблема в строке:

```
std::cin >> i >> x[i];
```

Программа должна сначала прочитать индекс `i`, а затем записать следующее число в `x[i]`.

Например, при вводе `3 77` правильный результат — `77`.

Но до стандарта C++17 порядок вычисления частей такой записи не был достаточно строго задан. Компилятор мог вычислить `x[i]`, используя старое `i = 0`, ещё до окончания первого ввода. Тогда значение 77 попадало бы в `x[0]`, а программа пыталась бы вывести `x[3]`, где осталось 0.

Поэтому у старых компиляторов могла возникать разница в результатах. Начиная с C++17 правила вычисления оператора `>>` задают нужный порядок.

Проверка с вводом `3 77`:

| Компилятор | Стандарт | Вывод |
|---|---|---|
| GCC 14.2 | C++14 | 77 |
| GCC 14.2 | C++17 | 77 |
| Clang 17 | C++14 | 77 |
| Clang 17 | C++17 | 77 |

В этих проверках оба компилятора выдали одинаковый результат. Найти два компилятора с разными результатами не удалось, поэтому не будем указывать вымышленные результаты.

Чтобы программа надёжно работала независимо от порядка вычисления длинного выражения, лучше разделить ввод:

```
std::cin >> i;
std::cin >> x[i];
std::cout << x[i];
```

Тогда сначала точно будет прочитан индекс, а только потом — элемент вектора.
